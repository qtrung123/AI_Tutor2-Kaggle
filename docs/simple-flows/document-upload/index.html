Upload tài liệu trong AI Tutor

Từ lúc chọn file PDF/TXT đến khi tài liệu được index và sẵn sàng để học. Chỉ hiển thị luồng thành công; lỗi được ghi chú riêng.

User Story

As a user, I want to upload my PDF or TXT study materials so that AI Tutor can index them and use them for chat, summaries, flashcards and quizzes.

User Journey

  1. Bấm nút tải tài liệu lên.
  2. Chọn một hoặc nhiều file PDF/TXT từ máy.
  3. (Tuỳ chọn) Chọn môn học hoặc tạo môn mới, rồi bấm “Upload”.
  4. Chờ trạng thái “Uploading and indexing…” — file lớn có thể mất vài phút.
  5. Thấy kết quả, ví dụ “1 file indexed (42 chunks)”.
  6. Tài liệu xuất hiện trong thư viện, sẵn sàng để chat, tóm tắt và làm quiz.

Sequence Diagram

Request Response

Lưu ý: khung loop: bước 3–6 lặp cho từng file. Khung opt: file cùng tên, cùng hash đã index thì được bỏ qua. Việc embed diễn ra bên trong add_documents(); sơ đồ tách riêng bước 4–5 cho dễ hiểu.

Giải thích

Frontend gửi các file trong một request POST /api/sources/upload. Backend kiểm tra đuôi .pdf/.txt, lưu file vào data/users/<user_id>/, rồi gọi index_files(). Mỗi lần chỉ một upload được index (khoá toàn cục), và việc này chạy trong thread riêng nên chat vẫn hoạt động.

Phân tích tài liệu (bước 3): backend đọc nội dung file, chia thành các chunk và xác định các topic (chương/chủ đề) của tài liệu, rồi gắn topic cho từng chunk.

Các chunk được embed bằng BGE-M3 (qua Ollama) và lưu vào ChromaDB (collection study_documents); thông tin tài liệu (hash, số chunk, topics) ghi vào registry SQLite. Request chỉ trả về 200 khi mọi thứ đã lưu xong.

Chi tiết kỹ thuật (tuỳ chọn)
  • Trước khi phân tích, mỗi file được tính hash SHA-256 để phát hiện file đã index.
  • PDF đọc theo trang (có chế độ layout dự phòng), TXT đọc nguyên văn; trang trống bị bỏ. Chunk 800 ký tự, chồng lấn 150.
  • topic_extractor tìm heading để xác định topic. Khi cấu trúc heading chưa chắc chắn (độ tin cậy < 0.85), hệ thống gọi Qwen2.5-7B để phân loại heading; nếu Qwen lỗi thì dùng kết quả tự tính. Đây là lần duy nhất Qwen được dùng khi upload.
  • File không đổi nhưng phiên bản topic đã cũ: chỉ trích xuất lại topic (refresh_topic_metadata()), không embed lại.
  • Bản deploy dùng PostgreSQL: vector lưu ở pgvector, registry ở PostgreSQL và file gốc được lưu thêm lên Supabase Storage trước khi index.

Thuật ngữ

Chunk
Một đoạn văn bản nhỏ (~800 ký tự) cắt từ tài liệu; là đơn vị để tìm kiếm khi chat.
Embedding
Biểu diễn ý nghĩa của chunk thành một vector số, để tìm các đoạn có nội dung gần với câu hỏi.
BGE-M3
Model embedding chạy trên Ollama, tạo vector 1024 chiều, hỗ trợ nhiều ngôn ngữ.
Qwen2.5-7B
Model ngôn ngữ (LLM) chạy trên Ollama; trong upload chỉ dùng để phân loại heading khi cần.
Topic
Một chủ đề/chương trong tài liệu, suy ra từ heading; dùng cho quiz, flashcard và kế hoạch học.
ChromaDB
Vector database lưu chunk, vector và metadata của từng người dùng.
SQLite registry
Bảng ghi danh sách tài liệu đã index: hash, số chunk, đường dẫn file, topics.
File hash (SHA-256)
“Dấu vân tay” của file, dùng để phát hiện file đã được index trước đó.

Trường hợp lỗi & ngoại lệ (ngoài sơ đồ)

  • 400 — không có file, file không phải PDF/TXT, chọn cả môn có sẵn lẫn tên môn mới, hoặc tên môn không hợp lệ. Kiểm tra trước khi ghi bất cứ thứ gì.
  • 404 — môn học được chọn không tồn tại.
  • 503 — (bản PostgreSQL) không lưu được file gốc lên storage; file không được thêm.
  • 500 — Ollama không chạy, thiếu model embedding, hoặc lỗi đọc/ghi dữ liệu.
  • File đã index (cùng tên, cùng hash): bỏ qua, báo “already in your library”.
  • PDF không có chữ (ví dụ bản scan): không tạo chunk, file không được index.
  • Qwen lỗi khi phân loại heading: vẫn dùng topic tự tính, upload không bị dừng.
  • Frontend hiển thị “Upload failed: …” kèm thông báo lỗi từ backend.
